使い方は3つだけ

Rust ツールチェーンか、リリースのバイナリだけ。上流の API キーは手元に置いたままです。

  1. 起動する

    cargo build --release
cp mask.toml.example mask.toml
# upstream.base_url / upstream.api_key を編集
./target/release/mask serve

  2. 接続先を、mask に向ける

    # OpenAI 互換のツール
export OPENAI_BASE_URL=http://127.0.0.1:8080/v1

# Claude Code
export ANTHROPIC_BASE_URL=http://127.0.0.1:8080
export ANTHROPIC_API_KEY=<gateway.token>

  3. あとは普段どおり使う

    いつもどおり名前を書けば、外へ出るのは記号だけです。ターミナルからは mask chat "…"、送る前に何が置き換わるか見たいときは mask check "…"。

安心してよい理由

検出の精度に頼らず、仕組みとして漏れを止めています。

  • 戻せないなら、送らない。送信の直前に本文を丸ごと検査し、実値が1つでも残っていればリクエストごと中止します（既定は block）。
  • 通さない経路がある。対応していないエンドポイントは 403。実値が別の形で外へ出る道を作りません。
  • 本物の API キーは外に出ない。鍵を持つのは mask だけ。クライアントに配るのは gateway.token です。
  • 対応表はディスクに残らない。実名との対応はプロセス内のメモリだけに置き、ログにも値を書きません。
  • 数字で確かめられる。各応答の X-Mask-* ヘッダと mask status に、置換・復元した件数が出ます。

できないこと

都合の悪い点も、そのまま書いておきます。

  • 一度も検出できなかった値は止められません。それを見つけるのが検出層の仕事で、カナリアテストが回帰を防ぎます。
  • 人名検出は辞書ベースです。統計モデルではないので、珍しい名前は dictionary.tsv に足してください。
  • base URL を変えられないサービスは対象外です。ChatGPT の web 版など、間に立てないものは通りません。
  • ストリーミングは最後にまとめて返します。正確さを優先し、上流の応答を復元してから送り出します。
