mask
三つの入口 多層防御 インジケータ 封筒 導入

実名は、LLMに渡らない。
mask が帰り道も保証する。

mask は LLM API の前に置くローカルゲートウェイです。 ユーザーは普段どおり名前・電話番号・住所を入力し、外部に出るのは ⟦人名7⟧ のような不透明な疑似名だけ。 応答は自動的に実名へ復元して戻ります。 エージェント (Claude Code など) はプロキシ経由で、人間はシェルから、 同じ保証の内側に入れます。

5分で試す 信頼性インジケータを見る
LLMクライアント / エージェント / シェル ──(実名入り)──▶ ┌──────────────┐ │ mask gateway │ 上流の出力 ◀──(実名に復元)── │ マスク・復元・ │ ◀─(疑似名)──┐ │ リークゲート・ │ │ │ インジケータ │──(疑似名のみ)──▶ LLM API └──────────────┘ 実値は絶対に通さない (fail-closed)

三つの入口、一つの保証

どの門から入っても、外に出る前に mask 層・リークゲート・インジケータを通ります。 弱い経路はありません。

エージェント プロキシ経由

OpenAI 互換 (/v1/chat/completions) と Anthropic 互換 (/v1/messages) の両プロトコルで待ち受けます。 base URL を変えるだけで、エージェントハーネスがそのまま繋がります。

# Claude Code など (Anthropic プロトコル)
export ANTHROPIC_BASE_URL=http://127.0.0.1:8080
export ANTHROPIC_API_KEY=<gateway.token>

# OpenAI 互換ハーネス
OPENAI_BASE_URL=http://127.0.0.1:8080/v1

シェル CLI

mask コマンドで、人間がターミナルから直接。 1プロンプトの往復 (chat)、送信前の確認 (check)、 信頼性の可視化 (status) ができます。

$ mask chat "山田太郎さんに連絡して"
山田太郎宛にご案内を送りました。
[mask] masked 1 / restored 1 / unresolved 0 / leak gate block

$ mask check "090-1234-5678 ..."
⟦電話3⟧ ...      # 何がマスクされるか先に確認

多層防御 — 「絶対に外に出さない」を構造で保証する

マスクの出来不出来に依存しません。検出し損ねた PII は、 最後の門で送信ごと棄却されます (fail-closed)。

  1. マスク層メッセージ本文・ツール引数 (JSON の中の文字列まで再帰的に) を疑似名に置換。NFKC 正規化で全角/半角の変種も同じ実体に束ねます。
  2. デフォルト拒否のルーティング上流へ転送するのは対応済みエンドポイントと allowlist に列挙したパスのみ。他はすべて 403。
  3. 送信前リークゲート送信直前にペイロード全体 (キー・ヘッダ含む) を走査し、セッションが一度でも検出した実値が残っていればリクエストを破棄。マスク漏れ・未知のフィールド・再出現がすべて同じ失敗 (送信されない) に収束します。
  4. ゲートウェイトークン本物の API キーはゲートウェイだけが持ちます。クライアントにはダミートークンを配る。LAN 公開時も認証は定数時間比較。
  5. カナリアテスト結合テストがモック上流の受け取った全バイトに既知 PII が含まれないことを検証。回帰は CI で止まります。

信頼性インジケータ — 保証は、見えなければ信じられない

mask は「自分が何を守ったか」を静かに守りません。3つの面で常時表示します: リクエスト単位のヘッダ、ゲートウェイ全体の /status、 そして CLI のインジケータパネル。数値のみ — 実値・トークン・経路は決して含みません。

レスポンスヘッダ 1リクエスト毎

すべての応答に X-Mask-* ヘッダが付きます。 エージェントハーネス・CLI・あなたのデバッグのどれからでも 「マスクされたか、復元しきれたか」が分かります。

X-Mask: on
X-Mask-In: v1/messages          # どの入口を通ったか
X-Mask-Leak-Gate: block
X-Mask-Masked: 3                # 置換した実値の数
X-Mask-Restored: 2              # 元に戻したトークンの数
X-Mask-Unresolved: 0            # 復元できなかったトークン(要注目)
X-Mask-Nonce: 734dc18c9d7a      # この応答用に鋳造されたもの

CLI パネル mask status

稼働中のゲートウェイから姿勢 (leak gate モード・NER・辞書・トークン) と 累積カウンタを引いて、ランプ付きで表示します。

$ mask status
mask gateway — reliability indicators
● leak gate        block  (fail-closed)
● session          global  (mapping table: 2 records)
● ner              ja_ginza detection on
● dictionary       0 terms
● gateway token    required (both entrances)
  requests         2
  entities masked  2
  tokens restored  2
  unresolved       0

ライブ・ステータス (このページから読み取り)

下のランプは http://127.0.0.1:8080/status を直接読みに行きます。 既定ではセキュリティのため拒否されます (fail-closed) — gateway.status_public = true を設定すると可視になります。 あなたのゲートウェイが丹麦 (表示) することを選んだときだけ、このページは数字を見ます。

○ ゲートウェイを探しています…
○ leak gate —
● session — (mapping table: — records)
○ ner — / dictionary — terms
● gateway token —
● requests — / entities masked — / restored — / leak blocks —
オフライン、または status_public 未許可 — どちらも想定どおりの挙動です。

封筒 — 対応表は暗号文だけでチームに渡す

マッピングテーブルは再識別の鍵。平文で出る経路は原理的に存在しません。 共有は暗号化された「封筒」でのみ行われます: argon2id による鍵導出 + XSalsa20-Poly1305 による封緘、 有効期限つき、パスフレーズ誤りでロック、使い捨て。

送り手

curl -s -X POST http://127.0.0.1:8080/admin/export \
  -H "Authorization: Bearer <gateway.token>" \
  -H "Content-Type: application/json" \
  -d '{"passphrase": "<チームのパスフレーズ>"}' \
  > handoff.maskbox

受け手

curl -s -X POST http://127.0.0.1:8080/admin/import \
  -H "Authorization: Bearer <gateway.token>" \
  -H "Content-Type: application/json" \
  -d "$(jq '. + {passphrase:
      "<パスフレーズ>"}' handoff.maskbox)"

管理APIはループバック限定。ネットワークを渡るのは封筒ファイルだけです。 衝突するトークンIDは上書きされず競合として報告され、誤った人物への復元が構造的に起きません。

導入 — 5分

Python 3.12+ と uv があれば十分です。

git clone <このリポジトリ> && cd mask
uv sync
cp mask.toml.example mask.toml
# mask.toml を編集: upstream.base_url / upstream.api_key
uv run mask serve

クライアント側の設定 (一度だけ)

クライアント設定
OpenAI 互換ハーネス / エージェント base URL = http://127.0.0.1:8080/v1
API key = 配布されたゲートウェイトークン (sk-mask 等のダミーでも可)
Claude Code など Anthropic プロトコル ANTHROPIC_BASE_URL = http://127.0.0.1:8080
ANTHROPIC_API_KEY = ゲートウェイトークン
シェル (人間) mask chat "…" / mask check "…" / mask status

辞書タイプ

dictionary.tsv に自分の用語を登録: person / org / location / address / phone / email / account 。検出取りこぼしを見つけたら、ここに足して運用で強くしていきます。

テスト

uv run pytest    # カナリアテスト込み。上流に実値が出ないことがここで証明される
mask — PII pseudonymization gateway. マッピングテーブルはプロセス内メモリのみ。
保証されること: セッションが検出した値は外部に出ない。保証できないこと: 一度も検出されていない値 (検出層の担当、カナリアが回帰ゲート)。
