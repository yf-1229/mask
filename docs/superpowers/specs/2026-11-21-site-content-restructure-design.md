# Design — mask サイトの内容再構成

## Intent / Why

`site/index.html` は内容は正確だが、初見の読者が「結局なにをすればいいのか」を掴めない。
原因は、設計者向けの専門語（三つの入口 / 多層防御 / 封筒 / fail-closed / カナリア）が
読者の移動順より先に出ていること。読者が求める **概要 → 使い方 → 具体的な例** の軸に
沿って再構成し、迷いを減らす。

## Decisions (approved with approach A)

- 言語は日本語のまま。既存の日本語トーンを維持。
- `site/index.html` 単一ファイルのまま。ビルド手順・依存は追加しない。
- デザインテーマ（`branchead_base_DESIGN.md`）は据え置き。既存の CSS トークン／
  コンポーネント（card / btn / badge / code / kv / steps 等）を再利用し、新規 CSS は最小。
- 既存の「多層防御 / インジケータ / 封筒」の深い内容は削除せず、
  3部を支える **「仕組み・保証」** として末尾に再配置する。

## Goals / Non-goals / Anti-goals

- Goals: 3部構成（概要 / 使い方 / 具体的な例）が一読で辿れること。
  「1リクエストの往復」が実出力で示されること。ナビ・検索パレットが新構成と一致すること。
- Non-goals: デザインの刷新、新しい機能追加、コード本体（`src/`）の変更。
- Anti-goals: 専門語を冒頭に戻すこと、外部リクエストの導入（CSP は維持）、
  情報量を削って README 丸投げにすること（それは却下した案 B）。

## Structure

1. **概要** — なぜ必要か・何をするかを冒頭3行で。既存の Request inspector を集約。
2. **使い方** — 導入3ステップ、base URL 差し替えだけという設定、3つの入口を
   「どれを選ぶか」で整理。クライアント設定カードをここへ。
3. **具体的な例** — 新規。1リクエストの完全な往復を CLI / API の実出力で提示:
   実名入り chat → マスク後ペイロード → LLM 応答 → 手元で復元。`X-Mask-*` も実例として配置。
4. **仕組み・保証** — 既存の防御5層・インジケータ・封筒をここへ再配置。

## Constraints

- CSP で外部リクエストを遮断する既存の設計を壊さない（フォントは data URI のまま）。
- ライブ・ステータス widget の JS / fetch 動作は維持。
- コピーボタン、コマンドパレット（⌘K/Ctrl K）、scrollspy、reveal アニメーションを維持。
- アクセシビリティ（skip link、aria、focus-visible、prefers-reduced-motion）を維持。

## What's left to the builder

- 既存セクションの並べ替えと見出し・ナビ番号の更新。
- 「具体的な例」セクションの新規マークアップ（既存 card / code / kv の再利用）。
- 検索パレットの `data-search` キーワードとアンカーを新構成に合わせて更新。
- 変更後、HTML の構造整合性と JS の参照 ID が壊れていないことを確認。
